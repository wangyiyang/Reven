# 飞书机器人对话式运营入口（候选稿审核推送 + 应用配置页面）

> 来源：GitHub Issue #119。2026-09-19 范围拍板：**只做候选稿审核推送**，关键词管理不做；事件接收采用 **WebSocket 长连接**（推翻 issue 原文的 webhook 回调默认决策）；凭证通过 **Web UI 前端配置页面** 管理。

## Goal

让 Reven 运营审核无需打开 Web UI：每日 RSS 筛选出候选稿后，自动推送飞书交互卡片给老板本人，在飞书内点按钮完成"采纳 / 忽略"；飞书应用凭证通过现有 integrations 页面配置，开箱即用、改配置不重启进程。

## Requirements

### 功能范围

1. **飞书应用配置页面**
   - 在现有 integrations 页面新增"飞书应用（机器人）"配置卡片（新 provider，与现有飞书 webhook 通知卡片并存、互不影响）。
   - 可配置项：app_id、app_secret（secret 存储）、白名单 open_id 列表、启用开关（public 存储）。
   - 提供连接测试：验证凭证可换取 tenant_access_token 并拉取 bot 信息。

2. **候选稿审核卡片推送**
   - 每日 discovery 筛选完成（run 结束）后，将全部待审核候选（status=candidate 且尚未推送过审核卡片）以交互卡片推送给老板。
   - 卡片内容：标题（中文标题优先）、摘要、来源、发布时间，每条候选带"采纳 / 忽略"按钮。
   - 推送失败的候选不标记，次日随下次 run 重新进入推送集合。

3. **按钮回调审核**
   - "采纳"等价于现有 confirm 流程：candidate → pushing → pushed（推 Notion Inbox），复用现有领域服务。
   - "忽略"等价于现有 ignore 流程：candidate → ignored。
   - 回调结果以 toast 即时反馈；候选已被处理（重复点/重放）时提示"已处理"，不报错。

4. **安全**
   - 写操作（按钮回调）强制校验操作者 open_id ∈ 白名单，非白名单拒绝并 toast 提示。
   - 长连接本身由 app 凭证认证；不额外配置 encrypt key / verification token。
   - 凭证存现有 integrations secrets 体系（SecretBox 加密），禁止硬编码。

### 非目标（本期不做）

- RSS 关键词管理（指令或卡片形式均不做）。
- RSS sources 管理。
- LLM 自然语言意图解析。
- 多租户 / 多用户权限体系。
- 替换现有飞书 webhook 出站通知（每日汇总通知保留原样）。

### 约束

- 单进程单部署：WebSocket 长连接挂现有 FastAPI 进程，不引入独立服务。
- 核心领域操作层与飞书协议适配层分离，未来 MCP Server 可直接复用核心层。
- 配置在前端保存后自动生效（进程内重建连接），无需重启容器。
- 面向单用户（老板本人）场景，IM 消息入口仅提供固定引导文案，不做指令系统。

## Acceptance Criteria

- [ ] integrations 页面可配置飞书应用凭证与白名单，连接测试通过；保存后进程内连接自动重建。
- [ ] 每日 run 完成后，待审核候选以交互卡片推送到飞书；已推送过的候选不重复推送。
- [ ] 点"采纳"按钮后候选走 confirm → pushed 流程推入 Notion Inbox；点"忽略"后候选变为 ignored；均有 toast 反馈。
- [ ] 非白名单 open_id 的按钮操作被拒绝并收到提示。
- [ ] 核心领域操作层（审核/推送逻辑）不依赖飞书 SDK，可独立测试。
- [ ] server 测试全绿，新增用例覆盖白名单校验、按钮回调解析（含重复处理）、推送候选选择逻辑、连接生命周期。
- [ ] web 端 integrations 相关测试全绿。
