# Agent 运行时迁移至 LangGraph 与数据库持久化

## 目标与用户价值

让 Reven 的经营助手在重启、超时、重复请求和人工确认场景下，仍能保留会话并核实业务操作结果；将 Agent 配置与状态纳入数据库管理，降低 DeepSeek Harness 子进程适配成本。

## 背景与证据

- 用户在综合架构评估后要求开始改造，2026-10-06 同意创建 Trellis 任务并进入规划；同日审阅方案后明确批准“开始实施”。
- 技术方向为 LangChain 简单 Agent（底层 LangGraph）与 PostgreSQL；Reven 当前是单用户、自托管 Alpha（`README.md:5,43`）。
- 工具范围为 RSS 4、CRM 15、人才 18，共 37 个，其中 25 个写工具、8 个删除工具；入口集中在 `server/src/reven/agent/mcp_server.py:46`。
- 当前 SDK 为同步 DSH 子进程；模型实例按模型引用缓存，会话冲突通过重铸 ID 继续，不能恢复历史（`agent/runtime.py:74,196`）；会话模型选择只存在内存（`agent/service.py:30`）。
- 默认 Agent 运行超时 180 秒，飞书等待 120 秒；停止等待不能保证底层停止写入（`agent/runtime.py:79`、`integrations/feishu_bot/chat_dispatcher.py:40,166`）。
- 删除客户仅核对名称一致，不验证独立的用户批准记录（`agent/tools_crm_customers.py:134`、`agent/crm_tool_support.py:106`）。
- CRM/Talents 服务及 RSS 工具自行提交事务；必须改造实际写入口才能与操作记录原子提交（`crm/service.py:26,109`、`agent/tools_rss.py:64`）。
- REST 当前请求严格校验，成功响应仅含 `session_id/response`；飞书会话为 `feishu:{chat_id}:{open_id}`，白名单每次现读（`api/schemas/agent.py:10`、`integrations/feishu_bot/chat_dispatcher.py:194`）。

## 范围与需求

| ID | 要求 | 可观察行为 |
| --- | --- | --- |
| R1 | 迁移执行核心并保持现有业务能力 | Agent 不再需要 DSH 子进程或本地 Workspace；现有 37 个工具及 REST、飞书入口可用 |
| R2 | 持久管理配置与会话 | Prompt、工具启用关系、配置版本、会话历史、模型选择和执行记录入库；新配置从下一轮生效，运行中保持快照 |
| R3 | 可信的持久确认 | 8 个删除工具先展示具体目标与影响；原发起用户明确批准后执行，待确认记录重启后仍可处理 |
| R4 | 防止同次操作重复写入 | 同一飞书消息或 REST 幂等请求只形成一次运行；同一工具调用重放复用已提交结果；人才画像重复导入不会因重放重复追加 |
| R5 | 可解释的中断与恢复 | 等待超时后用户能查询原运行结果；重启后未完成运行明确标识，不自动从头重复写入；原用户可恢复有安全检查点的运行 |
| R6 | 模型兼容与明确错误 | 继续使用 DeepSeek 官方及明确支持的 OpenAI 兼容端点；保留已有模型注册与加密密钥；未知协议或指定模型不可用明确失败，不静默换模型 |
| R7 | 业务与部署兼容 | RSS 分段执行、素材审核、经营模块网页和业务规则继续有效；给出新增数据库结构、容器配置、升级与回滚验证 |

## 交互与兼容约束

- REST `/api/agent/chat` 的现有请求字段与 `{session_id,response}` 成功结构保留；幂等使用可选请求头。配置、运行查询、批准/拒绝和显式恢复使用新增接口，不强迫旧客户端增加字段。
- 飞书继续私聊/群聊 @、原会话映射、白名单、引用回复和 `/model` 指令。删除确认使用明确的 `确认 <确认编号>` / `取消 <确认编号>`；状态查询与恢复使用原运行编号。
- 危险操作批准只授权展示的工具、目标与参数；模型话术、参数中的确认名称、另一人的回复均不能代替服务端批准。
- 模型切换与公开配置更新只影响后续新运行；批准或恢复时仍检查模型、工具和发起身份当前是否允许使用。
- 历史 DSH 卷保留归档；首期新运行时从新对话上下文开始，不承诺导入旧 DSH 对话或恢复旧工具执行状态。业务数据和已保存模型配置延续。此兼容边界列入最终方案审阅。
- 应用保持单管理员、单 worker；不增加租户体系或外部任务调度基础设施。

| AC4 | R3 | 未确认、错误用户、错误参数、重复确认、取消或已失效待办均不触发额外删除；批准后恰好一条业务操作提交记录 |
| AC5 | R4 | 相同 message_id/幂等键不重复写入；相同键不同输入明确冲突；不同消息的相同业务意图不被错误吞掉 |

| AC8 | R3、R5 | 同会话与同批工具的写入串行，等待确认时新写入不能抢跑；不同会话可并发；飞书 SDK handler 立即返回 |
| AC9 | R6 | DeepSeek/标准兼容端点的请求和响应协议验证；失效模型、密钥缺失或检查点不可用时明确降级，日志与公开响应不暴露密钥 |
| AC10 | R7 | PostgreSQL 空库升级、存量升级、新版容器只读根目录启动通过；旧 DSH 数据保留，回滚步骤可操作 |
| AC11 | 全部 | lint、format、mypy、数据库迁移与相关全量回归通过；真实模型验证和测试替身证据分别记录，任何跳过明确说明 |

## 不纳入本次范围

- 新增财务、项目、品牌或 SOP Agent 工具、跨域业务关系与统计口径。
- 多用户、多租户、Agent 可视化搭建平台、多 Agent 协作。
- 新建 Agent 聊天/配置前端页面；现有集成设置继续管理模型，新增 Agent 配置由 API 管理。
- 旧 DSH 对话的自动导入、旧运行状态转换；删除任何旧数据卷。
- Redis、Temporal、Agent Server 或自动重试整个业务运行。
- 生产部署、合并 PR、生产数据变更。
