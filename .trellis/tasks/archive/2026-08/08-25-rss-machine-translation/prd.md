# 百度/阿里机翻替代 RSS 聊天翻译

## Goal

让 RSS 新闻标题和摘要优先使用百度或阿里云专业翻译，不再与 SiliconFlow embedding 共享聊天模型配额；供应商限流或故障时自动切换，并彻底移除腾讯翻译支持。

## Background

- 生产实测中 788/2010 条候选处于 degraded 状态；聊天翻译与 embedding 共用零余额 SiliconFlow 账号是已知资源竞争点。
- 依赖 PR #85 已合并：翻译配置卡、加密凭证、`priority` / `enabled`、连接测试与低层客户端已存在，但 RSS 运行时仍在 `server/src/reven/rss/factory.py` 直接把 `SiliconFlowChatClient` 作为 `EntryLocalizer`。
- 用户已确认只保留百度和阿里翻译，移除腾讯翻译支持。
- 数据库可能已有 `translate_tencent` 配置。只移除前端卡片会让旧记录继续从 API 返回，并导致前端严格 provider 校验拒绝整个集成列表，因此要同时清理存量数据并在 API 边界过滤未知 provider。

## Confirmed Requirements

- 完整移除腾讯翻译的后端 provider 枚举、API schema、连接测试注册、客户端、前端类型/配置卡与相关测试。
- `translate_tencent` 不再是受支持 provider；其创建、更新、删除、连接测试等 provider 路由统一按未知 provider 返回 404。
- 新增精确数据迁移，仅删除 `provider = 'translate_tencent'` 的集成行及其中的密文凭证；该删除不可逆，降级迁移不尝试恢复密钥，恢复支持时需重新录入。
- 集成列表 API 只返回当前支持的 provider。即使迁移外仍存在未知旧行，也不能让它破坏整个前端列表。
- RSS 运行时从数据库加载启用且密钥完整的百度/阿里配置，不新增机翻环境变量。
- 按 `priority` 升序调用；同优先级时使用稳定顺序百度 → 阿里。
- 一家超时、限流、网络或业务错误不得中断整轮：当前条目切换到下一家，并在本次 localize 调用余下条目中停用已故障供应商，避免持续轰炸故障端点。
- 标题和摘要必须由同一家供应商完整翻译；任一字段失败时丢弃该条目的部分结果，由下一家从头重试。
- 标题与摘要按确定性边界分成不超过 1,000 字符的片段并按原顺序重组；空摘要不发请求；最终输出继续限制为标题 2,000、摘要 6,000 字符。
- 百度路径按 1 QPS 保守限速，使用可注入的时钟/休眠实现以便单测不真实等待。
- 首选及备用机翻均失败后，才使用现有 Qwen 聊天本地化作为最终兜底；不增加常驻 LLM 润色。未配置任何机翻时直接沿用该兼容路径。
- 最终翻译失败时保留现有 `PartialLocalizationError` 语义：成功条目不丢失，失败条目回退原文，RSS run 记录 translation 降级。
- 聊天模型的筛选复核能力与机翻解耦；`RSS_MODEL_REVIEW_ENABLED` 的现有行为保持不变。
- 凭证不出现在日志、异常、API 响应或测试快照中。

## Acceptance Criteria

- [ ] CMS 不再展示腾讯翻译卡片，前后端受支持 provider 均只有百度和阿里；`translate_tencent` 路由回归测试验证为 404。
- [ ] 数据迁移只删除 `translate_tencent` 行，保留其他 provider；集成列表 API 会过滤未知旧行，且测试不泄露密文。
- [ ] 仅启用且密钥完整的百度/阿里参与 RSS 翻译；优先级及百度 → 阿里的同级稳定顺序有单测。
- [ ] 首选供应商成功时不调用其他供应商或聊天模型。
- [ ] 首选供应商返回限流、5xx、超时或无效响应时，备用供应商能从标题开始完整重试当前条目，且后续条目不再调用已故障供应商。
- [ ] 单条超限标题/摘要被按不超过 1,000 字符分段翻译，输出顺序、空摘要处理和 2,000/6,000 存储长度边界有单测。
- [ ] 百度请求间隔满足 1 QPS，测试使用可控时钟/休眠，不产生真实等待。
- [ ] 所有机翻失败或未配置机翻时才调用 Qwen 兜底；兜底最终失败仅将对应条目标记为降级。
- [ ] `RSS_MODEL_REVIEW_ENABLED` 的筛选复核行为保持不变。
- [ ] 后端 Ruff、格式检查、mypy、Alembic upgrade 和 pytest 通过；前端 lint、类型检查、测试与构建通过。

## Out of Scope

- 不迁移到腾讯 TokenHub，也不保留旧腾讯 TMT 开关或兼容入口。
- 不改变 embedding 供应商、语义打分规则、筛选复核策略或历史 degraded 回填逻辑。
- 不引入自定义术语库、翻译记忆或翻译结果缓存。
- 不做每条新闻的常驻 LLM 标题润色。
- 不对真实生产凭证发起请求；真实连接/端到端验收需单独授权。

## Data and Rollback Note

执行迁移会永久删除现有腾讯翻译配置及其加密凭证。代码回滚不会恢复这部分数据；如未来重新支持腾讯，需要管理员重新录入凭证。
