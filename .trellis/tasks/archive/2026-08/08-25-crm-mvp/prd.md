# CRM 第一阶段 MVP

## Goal

为当前“一人公司操作系统”交付首个可用的 B2B CRM 垂直切片，使经营者能够集中维护客户与联系人、记录每次跟进，并始终明确下一步行动。

## Background

- 2026-07-19 的旧路线曾规划家电零售 CRM，但明确属于远期候选；旧代码只有空领域包，没有可用 CRM。
- 2026-07-29 项目重建后，Reven 已转为当前的一人公司操作系统。
- 当前产品已有统一登录、桌面/移动端导航、列表搜索筛选、CRUD、确认删除及错误提示等交互基础。
- 本期服务一人公司的 B2B 客户关系，不恢复消费者家庭、设备、安装或保修模型。

## Requirements

### R1 · CRM 入口与客户列表

- 主导航新增“CRM”，默认进入客户列表。
- 列表展示客户名称、关系状态、来源、当前下一步行动及跟进日期。
- 支持按客户/联系人关键词搜索，按关系状态与跟进时间范围筛选。
- 有明确的加载、空数据和请求失败状态；桌面使用表格，移动端使用卡片。

### R2 · 客户档案

- 客户字段包括：名称、关系状态、来源、备注、当前下一步行动、下次跟进日期。
- 关系状态限定为：`潜在客户`、`跟进中`、`合作客户`、`暂停跟进`、`已流失`。
- 支持创建、查看、编辑和确认删除客户；客户名称不强制唯一。
- 设置下次跟进日期时必须同时提供下一步行动。

### R3 · 联系人

- 每个客户可维护多个联系人。
- 联系人字段包括：姓名、职位、电话、邮箱、微信、主要联系人标记、备注。
- 支持联系人创建、查看、编辑和确认删除。
- 同一客户最多一个主要联系人；设置新的主要联系人时自动取消旧标记。

### R4 · 跟进记录

- 客户详情页按时间倒序展示跟进时间线。
- 跟进字段包括：方式、发生日期、关联联系人、内容、当时约定的下一步行动和日期。
- 跟进方式限定为：电话、会议、微信、邮件、其他。
- 支持创建、编辑和确认删除跟进记录。
- 新增跟进时，用户可明确选择是否把其中的下一步行动同步为客户当前行动；修正或删除历史记录不自动改写客户当前行动。

### R5 · 到期可见性

- 客户列表优先显示已有跟进日期的客户，并按日期由近到远排列。
- 逾期和今日待跟进必须有文字或图标语义，不能只依赖颜色。
- 本期只提供应用内可见性，不发送系统、邮件或飞书通知。

### R6 · 数据、安全与错误

- CRM 沿用当前单用户认证边界，所有接口均受现有认证和 CSRF 中间件保护。
- 数据库、API 与前端边界使用明确类型和输入校验；未知字段被拒绝。
- 邮箱、字段长度、枚举、日期/行动组合等无效输入返回明确错误，前端不得显示成功提示。
- 删除客户级联删除其联系人和跟进；删除联系人保留历史跟进，但解除联系人引用。
- 客户联系方式和跟进内容不得写入应用日志。

### R7 · 兼容与质量

- 页面遵循现有翊行代码 VI v2.1，不增加新品牌色或非必要依赖。
- 新增前端文件、函数与组件应按职责拆分，避免单文件超过 500 行、单函数超过 50 行。
- 后端 API、数据库迁移、级联规则和前端核心交互必须有自动化测试。

## Acceptance Criteria

- [x] AC1：登录后可从主导航进入 `/crm`；桌面和移动端均能浏览、搜索和筛选客户。
- [x] AC2：可创建、查看、编辑、删除客户，刷新后数据保持一致；五种关系状态均可保存与筛选。
- [x] AC3：可在 `/crm/customers/:customerId` 管理多个联系人，并保证同一客户最多一个主要联系人。
- [x] AC4：可新增、编辑、删除跟进记录，时间线倒序展示且删除联系人不会删除历史跟进。
- [x] AC5：新增跟进并选择同步后，客户当前下一步行动和跟进日期在列表及详情中同时更新。
- [x] AC6：逾期、今日、未来和无计划客户可正确筛选；逾期与今日状态具备非颜色语义。
- [x] AC7：无效输入、越属客户的嵌套资源、资源不存在和请求失败均有显式处理，不产生假成功。
- [x] AC8：删除客户前必须确认，删除后联系人和跟进同步清理且其他客户数据不受影响。
- [x] AC9：后端 lint、format、mypy、迁移与测试，以及前端 lint、测试和构建全部通过。

## Out of Scope

- 独立线索池、线索转客户、商机、多商机阶段管道和看板。
- CRM 与项目库、财务记录、稿件或外部通讯录的关联。
- 批量导入导出、重复客户合并、标签体系、自定义字段和分页。
- 营销自动化、群发触达、积分/会员、AI 自动决策和自动生成跟进内容。
- 站外提醒、定时任务、飞书通知和日历同步。
- 多租户、团队成员分配、细粒度权限和审计日志。

## Delivery Constraint

- 目标基线为 `origin/main`。本地 `main` 当前落后远端且工作区存在未提交内容；实施必须在隔离的 `codex/crm-mvp` 功能分支/工作树中完成，不得直接修改 `main` 或覆盖现有工作区。
