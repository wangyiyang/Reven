# PRD · #104 财务指标口径

## Goal

让财务汇总不再高估在手现金，并使页面承诺与实际指标一致。

## Confirmed Facts

- 当前 repository 的收入/花销汇总包含所有状态，净额为两者相减；应收/应付又单独计入对应卡片。
- 页面副标题承诺“跑道”，但数据模型没有现金余额、月均支出或预算，无法诚实计算真实跑道。
- 已关闭功能 Issue #45 曾把跑道列入远期汇总目标，但当前实现只交付五张汇总卡。

## Requirements

- 本轮删除副标题中的“跑道”，不伪造缺少基础数据的指标。
- 应收/应付继续分别统计 `income+应收` 与 `expense+应付`。
- “已收收入”仅统计 `income + 已收`，“已付花销”仅统计 `expense + 已付`，“现金净额”为两者之差。
- `已记录` 因现金状态不明确，不计入三张现金汇总卡；应收/应付继续独立展示。
- 卡片明确命名为“已收收入 / 已付花销 / 现金净额”，不依赖 tooltip 才能理解口径。

## Acceptance Criteria

- [x] 页面不再声称提供未实现的跑道指标。
- [x] ¥10,000 已收 + ¥2,000 应收时，三张核心卡按批准口径展示，且不会被误读为无说明的 ¥12,000 在手收入。
- [x] 服务端汇总测试覆盖已收、已付、应收、应付、已记录。
- [x] 前端卡片文案/说明与 API 语义一致。

## Out of Scope

- 新增真实跑道、月度归档、预算或现金余额模型。

## Key Decision

- 用户确认采用严格现金口径，不迁移或猜测现有 `已记录` 数据的支付状态。
