# 飞书机器人接入 Agent 对话

> 来源：2026-09-27 grill 拷问会话达成的设计共识（两轮问答，用户逐条确认）。延续 #119 铺好的 WebSocket 长连接管道，落实 `docs/agent-architecture.md:110-111` 早已预留的飞书接入约定（session_id = `feishu:{chat_id}:{user_id}`，与本层 `AgentService.chat()` 复用同一服务层）。

## Goal

让飞书机器人从「固定文案应答机」升级为 Reven Agent 的对话入口：白名单用户在私聊中、或在群聊中 @机器人，以自然语言提问，机器人把消息正文交给 `AgentService.chat()`，以引用回复形式返回智能答案。

现状：`server/src/reven/integrations/feishu_bot/handlers.py` 已通过 lark-oapi WebSocket 长连接接收 `im.message.receive_v1` 事件，但只处理私聊、丢弃消息正文、统一回固定引导文案。

## Requirements

### 功能范围

1. **私聊对话**
   - 白名单用户私聊发送文字消息 → 机器人接入 Agent 并回复智能答案。
   - 替换现有固定引导文案。

2. **群聊 @ 对话**
   - 仅当机器人被 @ 时响应；未被 @ 的群消息一律忽略。
   - 剥离 mention 占位符后剩余文本为空 → 回复引导文案（如「@我 并输入你想问的问题」）。

3. **回复策略（一次性，不做流式）**
   - 收到合法提问后立即**引用回复**一条「思考中…」。
   - Agent 算完后再**引用回复**一条最终结果（共两条消息，均按触发消息的 message_id reply）。
   - 群聊与私聊回复形式一致。

4. **会话映射**
   - session_id = `feishu:{chat_id}:{user_id}`，群内每人独立会话，与私聊逻辑同构。
   - 多轮记忆由后端 session 管理，飞书适配层不自行存历史。

5. **权限边界**
   - 复用现有 `whitelist_open_ids`，语义从「通知接收人」扩展为「机器人可用用户」；集成页配置文案同步注明。
   - 白名单外用户的消息（私聊/群聊）直接忽略，不回复任何内容。
   - MVP 不做每用户限流/配额，白名单即成本闸门。

6. **异常与超时兜底**
   - 单轮对话总超时 120 秒（硬编码，不做配置项）。
   - 超时或 AgentService 异常 → 引用回复简洁兜底文案（如「出了点问题，请稍后重试」），不向用户暴露堆栈，完整错误进服务端日志。

7. **非文本消息**
   - 图片/文件/表情等非 text 类型 → 统一回复「暂只支持文字提问」，不做图片理解。

### 非目标（本期不做）

- webhook / url_verification / encrypt_key（长连接模式豁免，#119 既定决策）。
- 流式输出、卡片协议（将来升级方向为「卡片局部更新」，届时替换「思考中」消息）。
- 图片/文件内容理解、群内共享记忆、每用户限流配额。
- RSS 关键词管理、指令系统。

### 约束

- 单进程单部署：沿用现有 WS 长连接，挂 FastAPI 进程，不引入独立服务、不引入公网回调入口。
- 飞书适配层只做渠道适配（解析/鉴权/回复），智能全部在 `AgentService`；禁止在适配层另起 LLM 调用。
- 配置热更新能力不退化：`supervisor.reload()` 后对话功能正常。
- 防自循环：只处理 `sender_type == "user"` 的消息，群聊场景同样适用（机器人/其他应用消息不响应）。

## Acceptance Criteria

- [ ] 私聊提问 → 先收到「思考中…」引用回复 → 收到答案引用回复；追问「继续」能接上上下文（同一 session）。
- [ ] 群聊 @机器人 提问行为同上；不 @ 则无响应；同群两名用户各问各的，上下文互不串（session 独立）。
- [ ] 白名单外用户发消息（私聊/群聊@）无任何响应。
- [ ] 发送图片/文件/表情 → 收到「暂只支持文字提问」。
- [ ] LLM 凭证失效或对话超过 120s → 用户收到兜底文案，服务端日志含完整错误。
- [ ] 在 integrations 页面修改飞书配置保存后（supervisor reload），对话功能仍正常。
- [ ] server 测试全绿，新增用例覆盖：mention 解析与空文本分支、白名单过滤、session_id 拼接、超时/异常兜底、群聊与私聊路由、非文本消息分支。

## Notes

- 人工前置确认：飞书开放平台上该应用需已开通群聊消息接收（`im:message` 相关事件对群聊生效）与「获取群组中用户@机器人消息」能力，若现有事件订阅不含群聊需在平台上补充。
- 长连接离线期间消息事件丢失，接受该语义（与 #119 一致）。
- 技术调研（lark-oapi 事件结构、线程桥模式、装配点、测试基座）见 `research/` 目录。
