## 步骤

1. **安装 gitleaks**：`brew install gitleaks`，验证 `gitleaks version`。
   - 验证点：版本号输出正常。
2. **全历史扫描**：按 design.md 命令扫描（--all、--redact），报告写 `research/gitleaks-report.json`。
   - 验证点：命令退出码 0/1（1 = 有命中，均正常）；报告文件生成。
3. **分诊命中**：jq 聚合 ruleID；逐命中定性（已知 31 / 假阳性 / 新增真实凭据）。
   - 验证点：每个命中在报告中有一行定性结论；新增真实凭据为零或已处置。
   - **回滚点**：若发现不可吊销凭据，停止实施，回到父任务重启历史重写决策。
4. **补充模式抽查**：`git grep` 对全历史快照跑高危模式（ghp_/github_pat_/AKIA/PRIVATE KEY 等），与 gitleaks 结果交叉。
   - 验证点：两路结果在报告中合并，无未覆盖盲区说明。
5. **撰写脱敏报告** `research/secret-scan-report.md`：执行摘要 + 明细表 + 吊销核对回执区。
   - 验证点：报告不含完整 secret 值（`grep -E "ghp_[A-Za-z0-9]{20,}"` 命中为零）。
6. **移交维护者动作**：提供 15 个 GitHub PAT 核对清单，维护者吊销后在回执区打勾。
   - 验证点：回执区 15 项全部标记"非本人"或"已吊销"。
7. **父任务对齐**：更新父任务验收标准 #2 状态。

## 完成定义

步骤 1-5、7 完成，步骤 6 的清单移交并等待维护者回执后，本子任务可归档（吊销回执作为归档前最后一项核对）。
