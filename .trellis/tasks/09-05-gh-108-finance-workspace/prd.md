# feat(finance): 按使用场景拆分财务页面并打通收付款流程

来源：GitHub Issue #108（labels: enhancement），关联 #45（财务模块初版）、#104（指标口径修正，现金口径需延续）。

## Goal

将财务模块从「汇总、录入、流水、应收应付集中在一页」重构为按使用场景组织的工作区，让用户能够快速了解经营情况、查询收支记录、处理待收待付款项。

用户价值：打开财务即知本月经营状况与待办事项；查账与录入互不干扰；待收待付从「登记」到「结清」有完整闭环，且只按实际收付日期计入现金流水。

## Confirmed Facts（代码与 Issue 证据）

**现状（仓库实现）**：
- 前端单页 `web/src/features/finance/finance-page.tsx`（409 行）：5 张汇总卡 + 常驻录入表单 + 单一列表纵向堆叠；筛选仅 kind + 名称搜索；无到期日录入、无确认收付流程。
- 路由 `web/src/app.tsx:38`：`/finance` → `FinancePage`；侧边栏「财务」入口 `web/src/components/app-shell.tsx:49`。
- 后端 `server/src/reven/finance/`：单表 `FinanceEntry`（kind: income/expense；status: 已记录/应收/已收/应付/已付；字段含 occurred_on、due_on、source、category、notes、recurrence）。
- API `server/src/reven/api/routes/finance.py`：`GET/POST /api/finance/entries`、`GET/PUT/DELETE /api/finance/entries/{id}`、`GET /api/finance/summary`；summary 为**全时段**汇总，实收只统计「已收」、实付只统计「已付」（repository.py:53-68，现金口径）。
- 现有数据模型**无需新增字段**即可承载首版（due_on/source 已存在但前端未录入）。
- UI 组件库无 Drawer/Sheet 组件（web/src/components/ui/ 仅 badge/button/card/dialog/input/label/select/separator/skeleton/table/tabs/textarea/tooltip）；tabs.tsx 已存在但未被业务页面使用。

**Issue 明确的方向**：
- 三个可直接访问、刷新和返回的子页面；`/finance` 入口继续有效。
- 新增/编辑改为抽屉，四种业务入口：记收入、记支出、新增待收、新增待付；按入口确定收支方向与业务状态，用户不再手动组合类型与状态。
- 概览：本月实收、实付、收支净额（标明周期）+ 逾期与近期到期款项摘要（近期 = 未来 7 天，日期边界按 Asia/Shanghai）。
- 流水：月份、收入/支出、分类筛选与搜索；主体列表只展示实际收付款（已收/已付）。
- 待收待付：待收/待付切换；按逾期、近期到期、以后到期分组；确认收款/付款填实际日期后结清。
- 确认后按**实际收付日期**归属流水月份，同一笔业务无需再次手动新增；首版整笔确认，分期/部分收付不做。
- 确认失败保留原状态并明确提示；重复确认不得重复记账。
- 缺失到期日期的历史待收付款仍可查找并补录。

## Requirements

### R1 三个独立子页面与导航

- R1.1 财务一级入口保留，三个子页面各自拥有独立 URL，可直接访问、刷新、返回：
  - 财务概览（默认落地页）：本月实收、本月实付、收支净额（金额标注统计周期）；逾期与近期到期款项摘要；点击摘要进入待收待付页对应筛选结果。
  - 收支流水：仅展示已发生的收付款（已收/已付），支持月份、收入/支出、分类筛选与名称搜索，支持查看详情与编辑。
  - 待收待付：待收/待付切换；按逾期、近期到期（未来 7 天）、以后到期分组；缺失到期日期的记录归入可识别分组并可补录到期日期。
- R1.2 概览的现金汇总不混入待收待付金额；收支净额 = 本月实收 − 本月实付，不代表账户余额。
- R1.3 桌面端与移动端均可完成：查看概览、查询流水、新增记录、确认收付款。

### R2 抽屉式业务动作录入

- R2.1 新增与编辑通过抽屉完成，不再常驻列表上方。
- R2.2 四个入口及字段：
  - 「记收入」：名称、金额、实际收付日期，分类可选。提交后 kind=income、status=已收。
  - 「记支出」：名称、金额、实际收付日期，分类可选。提交后 kind=expense、status=已付。
  - 「新增待收」：名称、金额、收付款对象（轻量文本）、预计收付日期，备注可选。提交后 kind=income、status=应收、due_on=预计日期。
  - 「新增待付」：名称、金额、收付款对象、预计收付日期，备注可选。提交后 kind=expense、status=应付。
- R2.3 用户不必手动选择类型与状态组合；新流程不再产生「已记录」状态的新记录。
- R2.4 收付款对象首版为轻量文本，不接 CRM、不关联项目。

### R3 待收付到流水的流程打通

- R3.1 待收/待付记录可点击「确认收款」/「确认付款」，填写实际收付日期（默认当天，Asia/Shanghai）后结清：应收→已收、应付→已付，occurred_on 更新为实际收付日期。
- R3.2 结清后款项从未结清列表移出，且仅计入**实际收付日期所在月份**的流水与汇总；不沿用创建日期或预计到期日期。
- R3.3 同一笔业务保留关联，确认后无需再手动新增收入/支出。
- R3.4 幂等：重复确认不得重复计入流水或汇总；确认失败（如网络错误、状态已变更）保留原状态并明确提示。
- R3.5 首版仅支持整笔确认；实际金额与预期不符时，先编辑记录再确认。
- R3.6 历史「已记录」：新流程不再产生「已记录」记录；现金口径天然将其排除在汇总之外（不改变现有口径，无需任何迁移）。首版不提供专门的待确认入口（依据：2026-09-05 用户确认线上无历史数据，见 Decisions D1）；若未来出现此类数据，记录仍完整保留在数据库且 API 可读写，届时再补人工确认入口。

## Acceptance Criteria

- [ ] AC1 财务概览、收支流水、待收待付均可通过独立 URL 访问；原 `/finance` 入口可正常进入财务模块。
- [ ] AC2 概览默认展示本月实收、实付和收支净额并标明统计周期；待收待付金额不混入现金汇总。
- [ ] AC3 概览中的逾期、近期到期事项可点击进入待收待付页对应筛选结果，并能继续处理款项。
- [ ] AC4 收支流水支持月份、收入/支出、分类筛选与搜索；主体列表只展示实际收付款。
- [ ] AC5 待收待付支持待收/待付切换与到期分组（逾期/近期到期/以后到期）；「日期未定」分组容纳缺失到期日期的记录并可补录。
- [ ] AC6 新增与编辑使用抽屉；四种业务入口展示对应字段；用户不必手动选择类型与状态组合。
- [ ] AC7 一笔跨月待收款确认到账后，从未结清列表移出，并仅计入实际到账月份的收入；待付款同理。
- [ ] AC8 确认失败不会提前结清；重复确认不会重复计入流水或汇总。
- [ ] AC9 新流程不产生「已记录」状态记录；「已记录」记录（若存在）不计入任何现金汇总，也不出现在流水与待收待付列表；上线前通过 SQL 确认线上无遗留「已记录」数据，若有则人工处理后再发布。
- [ ] AC10 桌面端与移动端均可完成查看概览、查询流水、新增记录及确认收付款的完整流程。

## Out of Scope

- 订阅续费、银行同步、预算、自动催款。
- 客户/项目关联（CRM 集成）。
- 分期、部分收付款。
- 账户余额、经营跑道、利润等指标。
- 历史「已记录」数据的自动迁移/批量推断与专门确认入口（首版无此类数据，见 D1）。

## Decisions

- D1（2026-09-05，用户确认线上无历史数据）**首版不做「已记录」待确认入口**：数据前提不存在（YAGNI）；新流程不再产生「已记录」；现金口径天然排除该状态，无数据污染风险；后端 API 保持对「已记录」的读写兼容，未来真出现数据时补一个筛选入口即可（复用确认对话框，成本约半天）。Issue 原验收项「历史已记录可被发现和人工确认」因此改写为口径保障 + 上线前 SQL 核查（AC9）。
