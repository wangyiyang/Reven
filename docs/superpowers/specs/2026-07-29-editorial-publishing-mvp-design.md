# Reven 内容发布工作台 MVP 设计

## 1. 结论

Reven 第一版是一个单用户内容发布工作台，目标是打通：

```text
Notion 稿件库
    → Reven 自动同步与调度
    → 博客自动上线
    → 微信公众号自动生成草稿
    → 飞书通知结果
```

第一版只解决 Notion 稿件发布，不依赖 OpenClaw，不处理 RSS 线索，不建设完整内容 CMS。

系统采用：

- 前端：React、TypeScript、Vite、shadcn/ui、Tailwind CSS、pnpm。
- 后端：Python 3.12、FastAPI、SQLAlchemy、Alembic、uv。
- 数据库：Supabase Postgres。
- 部署：`dev.wangyiyang.cc`，Caddy 自动 HTTPS，一个 Reven 容器。
- 架构：前后端代码分离、后端模块化单体、整体统一部署。

## 2. 背景

当前内容发布流程分散在多个工具中：

1. 在 Notion 稿件库中写稿。
2. 将 Notion 页面转换为 Jekyll 博客文章。
3. 在 Git 仓库中构建、提交和发布博客。
4. 使用 Doocs Markdown 生成微信公众号 HTML。
5. 复制内容到微信公众号平台。

频繁切换工具是主要痛点。用户仍希望使用 Notion 和 Notion AI 写稿，因此 Reven 不替代 Notion 编辑器，只接管写稿后的同步、校验、调度和发布。

## 3. 目标

### 3.1 产品目标

- Notion 是稿件正文的权威来源。
- 用户把稿件状态改为“待发布”后，后续流程自动执行。
- 博客通过 GitHub Flow 自动创建 PR、等待 CI、自动合并并确认上线。
- 微信公众号自动生成草稿，最终公开发布由用户在微信平台确认。
- 发布结果和错误通过飞书机器人主动通知。
- 所有任务可追踪、可安全重试、不会重复发布。

### 3.2 成功标准

- Notion 稿件能稳定同步到 Reven。
- “待发布”状态能在一个同步周期内被识别。
- 发布计划能按 `Asia/Shanghai` 正确执行。
- 博客能完成转换、构建、PR、CI、合并和线上验证。
- 微信草稿能包含正确标题、封面、正文样式和微信托管图片。
- 缺少封面或凭据无效时，发布被明确阻止。
- 服务重启后，未完成任务可以恢复。
- 同一稿件版本重试不会生成重复 PR、博客文章或微信草稿。
- Token、AppSecret 和数据库凭据不出现在前端、日志或飞书消息中。

## 4. 非目标

第一版明确不包含：

- OpenClaw 接入。
- RSS 抓取、关键词过滤和线索工作台。
- Supabase Storage、MinIO 或其他对象存储。
- Redis、独立消息队列、微服务或 Kubernetes。
- 微信公众号自动公开发布。
- 自动生成封面。
- 掘金、CSDN 等其他渠道发布。
- 多用户、组织、角色与权限系统。
- AI 写稿、原创性自动改写和内容数据分析。

这些能力只有在核心发布闭环跑通后再评估。

## 5. 系统边界

```text
浏览器
   │
   ▼
Caddy · dev.wangyiyang.cc
   ├─ /        → React 静态前端
   └─ /api/*   → Reven 后端
                    ├─ Notion 同步
                    ├─ 发布前校验
                    ├─ 定时调度
                    ├─ 博客发布
                    ├─ 微信草稿
                    └─ 飞书通知
                         │
                         ▼
                  Supabase Postgres
```

### 5.1 架构定义

- 前端和后端在代码与构建层分离。
- 后端只有一个运行服务，不拆独立 Worker。
- 调度器和发布执行器运行在后端进程内部。
- API 请求只创建或查询任务，不在请求生命周期执行长任务。
- 后台任务状态持久化到 Postgres。
- 各业务模块在进程内直接调用，不通过内部 HTTP。
- Caddy 统一提供 HTTPS、静态文件和 `/api` 反向代理。

这不是微服务架构。

### 5.2 模块职责

| 模块 | 职责 |
| --- | --- |
| Notion 同步 | 查询稿件库、映射字段、检测状态与内容变化 |
| 稿件 | 展示稿件元数据、校验结果和渠道状态 |
| 调度 | 计算执行时间、创建任务、恢复过期任务 |
| 博客发布 | 转换文章、操作 Git、创建 PR、等待 CI、确认上线 |
| 微信发布 | 渲染 HTML、上传图片和封面、创建草稿 |
| 集成配置 | 加密保存并测试 Notion、GitHub、微信和飞书配置 |
| 通知 | 发送去重后的飞书成功、阻塞和失败消息 |

### 6.1 现有稿件库

继续使用当前稿件库：

- Database ID：`3301a325-8142-4ba2-9d77-2d8fc96e59b0`
- Data Source ID：`4f7889bf-0a2c-4e3d-ac28-d9beac5cb239`

### 6.2 使用的现有字段

| Notion 字段 | 用途 |
| --- | --- |
| 标题 | 稿件标题 |
| 状态 | 人工写作和交付状态 |
| 目标渠道 | 决定博客与微信任务 |
| 计划发布日 | 决定立即或定时执行 |
| 系列 / 标签 | 博客分类与标签 |
| 摘要 / 核心观点 | 博客摘要和微信摘要候选 |
| 链接 | 博客上线后回写文章链接 |

### 6.3 需要增加的字段

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| 封面 | Files | 至少有一张可下载图片；MVP 只处理第一张 |
| 自动化状态 | Select | 未开始、等待中、处理中、阻塞、失败、已完成 |
| 失败原因 | Rich text | 只保存最近一次脱敏错误摘要 |

`状态` 增加两个选项：

- `待发布`：唯一自动发布指令。
- `已交付`：博客上线且所有目标渠道自动化任务完成。

保留现有 `已发布`，由用户在微信公众号正式发布后手动设置。

### 6.4 渠道规则

- 支持的目标渠道只有 `个人博客` 和 `微信公众号`。
- 目标渠道为空时，默认同时执行博客和微信，并发送飞书提示。
- 如果选择了 `掘金`、`CSDN` 等未支持渠道，发布进入阻塞，不静默忽略。

### 6.5 时间规则

- 所有业务时间以 `Asia/Shanghai` 展示和计算。
- 数据库存储 UTC 时间。
- `计划发布日` 包含时间时，按该时间执行。
- 只有日期时，在当天上海时间 `08:01` 执行。
- 没有计划日期时，进入“待发布”后立即执行。

## 7. 核心数据模型

### 7.1 `articles`

保存 Notion 稿件索引，不作为正文权威来源。

主要字段：

- `id`
- `notion_page_id`，唯一
- `title`
- `notion_status`
- `automation_status`
- `target_channels`
- `planned_at`
- `cover_metadata`
- `notion_last_edited_at`
- `last_error`
- `last_synced_at`
- `created_at`
- `updated_at`

### 7.2 `publication_jobs`

一行代表一个稿件版本的一次发布交付，博客与微信使用同一内容快照。

主要字段：

- `id`
- `article_id`
- `content_hash`
- `target_channels`
- `scheduled_at`
- `source_markdown`
- `snapshot_metadata`
- `wechat_html`
- `overall_status`
- `blog_status`
- `wechat_status`
- `blog_result`
- `wechat_result`
- `blog_error`
- `wechat_error`
- `attempt_count`
- `lease_expires_at`
- `started_at`
- `finished_at`
- `created_at`
- `updated_at`

唯一键：

```text
article_id + content_hash + target_channels_hash
```

这保证同一稿件版本和同一渠道组合不会被重复发布。

### 7.3 `integrations`

保存业务集成配置：

- `provider`：notion、github、wechat、feishu，唯一
- `public_config`
- `encrypted_secret`
- `connection_status`
- `last_tested_at`
- `last_error`
- `created_at`
- `updated_at`

### 7.4 `system_state`

保存少量系统游标和运行状态，例如：

- Notion 最近同步时间。
- 调度器最近心跳。
- 数据库结构版本之外的系统级键值。

## 8. 状态机

### 8.1 Notion 人工状态

```text
选题池 → 撰写中 → 待发布 → 已交付 → 已发布
```

- Reven 只自动写入 `已交付`。
- Reven 不自动写入 `已发布`。

### 8.2 Reven 自动化状态

```text
未开始
  → 等待中
  → 处理中
  → 已完成

校验问题 → 阻塞
临时或外部错误 → 失败
```

- `阻塞` 表示必须修改内容或配置。
- `失败` 表示任务执行异常，可以自动或人工重试。

### 8.3 渠道状态

博客：

```text
待处理 → 转换中 → 构建中 → PR 已创建 → 等待 CI → 合并中 → 已上线
```

微信：

```text
待处理 → 渲染中 → 上传图片 → 上传封面 → 创建草稿 → 草稿已生成
```

一个渠道失败不回滚另一个渠道。重试只执行失败渠道。

## 9. 端到端流程

### 9.1 Notion 同步

1. 后端按固定周期查询稿件数据源。
2. 通过 `notion_page_id` 更新或创建本地 `articles`。
3. 同步标题、状态、渠道、计划时间、封面和最后编辑时间。
4. 状态为“待发布”时进入调度判断。
5. 非“待发布”的未启动任务不执行。

如果待执行前用户把状态移出“待发布”，对应等待任务取消。

### 9.2 创建发布任务

1. 解析计划时间。
2. 解析目标渠道；为空时使用博客与微信。
3. 到达执行时间后重新获取最新 Notion 页面。
4. 执行发布前校验。
5. 生成 Markdown 内容快照和 SHA-256 内容哈希。
6. 按唯一键查找已有任务。
7. 不存在时创建任务，存在时继续或返回已有结果。

计划执行前对 Notion 的修改会进入最新快照。任务开始后内容版本冻结。

### 9.3 发布前校验

必须全部满足：

- 标题非空。
- 正文非空。
- `封面` 字段存在且图片可下载。
- 目标渠道均为 MVP 支持渠道。
- Notion 连接正常。
- 目标为博客时，GitHub 配置与仓库权限正常。
- 目标为微信时，微信配置、Token、素材和草稿权限正常。
- 飞书配置单独校验；飞书异常不阻止内容发布，但记录并展示告警。
- 微信标题、作者、摘要和正文满足接口长度限制。

校验失败时：

- 不启动任何目标渠道。
- Notion `自动化状态` 写为“阻塞”。
- `失败原因` 写入可操作的错误摘要。
- 飞书发送一次阻塞通知。
- 用户修复后，下次同步自动重新校验，不需要切换状态。

### 9.4 博客发布

1. 复用 `writing-agent-skills/notion-to-blog` 的页面转换、图片处理和 Jekyll 约定。
2. 将脚本中的直接推送行为改为可复用转换模块。
3. 在隔离临时目录准备博客仓库。
4. 从目标仓库默认分支创建唯一发布分支。
5. 生成 `_posts` Markdown 和 `images/posts` 图片。
6. 执行 Jekyll 构建验证。
7. 创建原子 Commit。
8. 推送发布分支并创建 PR。
9. 等待必要 CI 检查通过。
10. 自动合并 PR。
11. 等待 GitHub Pages 部署完成。
12. 访问预期文章 URL，确认 HTTP 成功且页面包含文章标题。
13. 保存 PR、Commit、部署和文章链接。
14. 将博客链接回写 Notion `链接` 字段。

任何情况下都不直接向目标仓库默认分支推送。

### 9.5 微信草稿

1. 使用 Doocs Markdown 渲染能力将 Markdown 转为微信兼容 HTML。
2. 通过本地 Node 渲染适配器调用，不部署独立渲染服务。
3. 下载正文中的 Notion 图片到临时目录。
4. 调用微信图片上传接口。
5. 将 HTML 中的图片地址替换为微信返回的地址。
6. 将 Notion `封面` 上传为微信永久素材，获得 `thumb_media_id`。
7. 调用 `/cgi-bin/draft/add` 创建草稿。
8. 保存微信 `media_id`、最终 HTML 和完成时间。
9. 在稿件详情中展示最终 HTML，并支持复制富文本。

Supabase Storage 和其他对象存储不参与正文图片访问。

个人订阅号只自动生成草稿，不调用公开发布接口。

### 9.6 完成交付

所有目标渠道成功后：

1. Notion `状态` 写为“已交付”。
2. Notion `自动化状态` 写为“已完成”。
3. 清空 `失败原因`。
4. 飞书发送交付摘要。
5. 清理本地临时文件。

用户在微信公众平台检查并正式发布后，手动把 Notion 状态改为“已发布”。

## 10. 工作台设计

### 10.1 稿件页

展示：

- 标题
- Notion 状态
- 自动化状态
- 封面校验
- 目标渠道
- 计划时间
- 博客状态
- 微信状态
- 最近同步时间

支持：

- 按状态和渠道筛选。
- 搜索标题。
- 打开 Notion 页面。
- 立即同步。
- 查看任务详情。
- 重试失败渠道。

### 10.2 稿件详情

展示：

- Notion 元数据。
- 发布前校验结果。
- 内容版本哈希。
- 博客和微信步骤状态。
- 脱敏错误信息。
- PR、Commit、博客文章链接。
- 微信草稿 `media_id`。
- 微信 HTML 预览。

操作：

- 打开 Notion。
- 生成无副作用的微信预览。
- 复制 `text/html` 富文本。
- 重试失败渠道。
- 取消尚未开始的计划任务。

### 10.3 集成设置

配置四个集成：

| 集成 | 公共配置 | Secret |
| --- | --- | --- |
| Notion | Database/Data Source ID | API Token |
| GitHub | Owner、Repo、默认分支策略 | Fine-grained Token |
| 微信 | AppID、作者信息 | AppSecret |
| 飞书 | 通知名称 | Webhook URL |

规则：

- Secret 只允许写入、替换和删除，不允许读取明文。
- 前端只显示“已配置”和脱敏摘要。
- 每个集成提供独立“测试连接”操作。
- 测试默认使用无副作用接口。
- 飞书测试消息只有用户主动点击时发送。
- 微信页面展示云服务器出口 IP，帮助配置微信 IP 白名单。

## 11. 安全设计

### 11.1 访问控制

- Caddy 为工作台启用 Basic Auth。
- Basic Auth 使用独立密码，不复用 SSH 密码。
- Reven 后端只绑定本机或 Docker 内网端口。
- 公网只开放 Caddy 的 80/443。
- HTTP 自动跳转 HTTPS。

第一版不引入 Supabase Auth。

### 11.2 Secret 管理

- `DATABASE_URL`、`REVEN_MASTER_KEY` 和 Caddy 密码哈希只存在服务器环境变量。
- Notion、GitHub、微信和飞书 Secret 通过 HTTPS 提交给后端。
- 后端使用版本化的 AES-256-GCM 密文保存到 Supabase。
- 解密只发生在执行集成调用的后端进程内。
- Access Token 由后端缓存和刷新，浏览器不可见。
- API 响应、应用日志和飞书通知统一执行脱敏。

## 12. 幂等、重试与恢复

### 12.1 幂等

- 任务唯一键防止同一稿件版本重复发布。
- 博客分支名包含稿件标识和内容哈希。
- GitHub 重试前先查询已有分支和 PR。
- 微信成功返回 `media_id` 后立即持久化，后续重试不重新创建草稿。

### 12.2 错误分类

| 类型 | 示例 | 处理 |
| --- | --- | --- |
| 阻塞 | 缺封面、凭据错误、权限不足、渠道不支持 | 等待用户修复，自动重新校验 |
| 临时失败 | 超时、限流、外部 5xx | 退避重试最多三次 |
| 永久失败 | 内容不符合微信限制、CI 持续失败 | 停止并等待人工处理 |

### 12.3 服务恢复

- 执行中的任务持有数据库租约。
- 后端周期性续租。
- 服务重启后，过期租约任务回到可执行状态。
- 渠道结果持久化，恢复时只继续未完成步骤。
- 临时目录丢失时重新拉取所需资源；若 Notion 内容哈希已变化，则阻塞旧任务，避免混合版本。

## 13. 飞书通知

通知事件：

- 目标渠道为空并使用默认博客与微信。
- 发布前校验阻塞。
- 单个渠道失败。
- 博客上线。
- 微信草稿生成。
- 所有目标渠道完成。

通知包含：

- 稿件标题。
- 当前阶段。
- 可操作的错误摘要。
- Notion 页面链接。
- Reven 稿件详情链接。
- 成功时的博客或 PR 链接。

相同任务、相同状态和相同错误指纹只发送一次。状态变化或人工重试后才允许再次通知。

## 14. 部署

### 14.1 云服务器

- 主机：现有 Ubuntu 22.04 云服务器。
- 域名：`dev.wangyiyang.cc`。
- 现有 3000 端口服务保持不变。
- Reven 不使用服务器已有 PostgreSQL 和 MinIO。
- Reven 后端使用独立端口，例如 `127.0.0.1:8000`。
- Caddy 使用 80/443 并自动申请、续期 HTTPS 证书。

### 14.2 部署单元

- 一个 Reven 容器：
  - Python API 和后台任务。
  - React 静态构建产物。
  - Doocs Node 渲染适配器。
  - Jekyll 博客构建所需运行环境。
- 一个 Caddy 容器或主机服务。
- 一个远程 Supabase Postgres。

不部署本地数据库、对象存储、Redis 或消息队列。

- GitHub PR、CI、合并与部署响应。
- 微信 Token、素材、图片和草稿响应。
- 飞书 Webhook 响应。

默认测试不得调用真实外部写接口。

### 15.3 集成测试

- 使用测试 Notion 页面验证同步与状态变化。
- 使用测试分支验证博客转换和构建。
- 使用 GitHub 测试 PR 验证自动合并链路。
- 在用户明确触发后创建一篇微信测试草稿。
- 验证服务重启后的任务恢复。

### 15.4 前端测试

- 稿件列表与筛选。
- 任务状态展示。
- 集成配置脱敏。
- 微信 HTML 预览。
- HTTPS 环境下复制 `text/html` 富文本。

### 15.5 CI 验证

- Python：Ruff、Mypy、Pytest。
- 前端：类型检查、测试、生产构建。
- 容器：镜像构建。
- 规格与迁移：Alembic 升级检查。

## 16. 验收流程

使用一篇专门的 Notion 测试稿件：

1. 配置四个集成并通过连接测试。
2. 同步稿件到 Reven。
3. 验证缺封面时进入阻塞并收到飞书通知。
4. 补充封面，验证自动解除阻塞。
5. 设置一个未来的具体发布时间，验证定时调度。
6. 验证博客 PR、CI、自动合并和线上文章。
7. 验证微信公众号草稿内容、图片和封面。
8. 验证 Notion 状态变为“已交付”。
9. 对同一任务执行重试，确认没有重复博客或微信草稿。
10. 在执行中重启 Reven，确认任务恢复。

全部通过后，MVP 视为完成。
