# 后续集成

先完成 [RSS → Notion 首次验收](self-hosting.md)。以下集成由使用者自行申请账号、开通接口与承担费用；项目不提供共享凭据，服务商免费额度、账单和权限以自己的账户为准。

## 按流程选择

| 能力 | 配置位置 | 首次 RSS 是否必需 | 未配置时 |
| --- | --- | --- | --- |
| Notion 稿件库与 Inbox | 集成设置 → Notion | 推送 Inbox 必需 | 可查看 RSS 候选，不能推送 |
| 百度 / 阿里翻译 | 集成设置 → 对应翻译服务 | 否 | 按优先级故障切换；都不可用时尝试 Qwen，仍不可用则保留原文 |
| Embedding | 集成设置 → Embedding | 否 | 字面与 BM25 筛选，显示语义降级 |
| Qwen 复核与翻译回退 | 自托管 `.env` 中 `SILICONFLOW_API_KEY` 等 | 否 | 模型复核跳过或降级；不影响人工判断 |
| Agent LLM | 集成设置 → Agent LLM | 否 | Agent 不可用；配置后需重启 Reven |
| 飞书通知 | 集成设置 → 飞书 | 否 | 不发送群机器人通知 |
| 飞书交互机器人 | 集成设置 → 飞书应用 | 否 | 继续在网页完成人工筛选 |
| 腾讯云 COS | 自托管 `.env` | 否；完整稿件同步必需 | 完整同步报 `COS_NOT_CONFIGURED`，不能交付稿件 |
| 微信公众号 | 集成设置 → 微信 | 否 | 不创建公众号草稿 |
| GitHub 博客 | 集成设置 → GitHub | 否 | 博客链路仍有固定站点限制，见下文 |

环境变量的可选项在 [示例文件](../infra/self-host/.env.example) 中保持注释；启用时填入自己的值，不使用空字符串伪装已配置。修改文件后执行 `dc up -d --force-recreate --wait reven`，其中 `dc` 沿用自托管指南的定义。UI 中的集成 Secret 加密保存在数据库中。

翻译、Embedding、Qwen 和 Agent LLM 是不同的配置与计费入口。只填写 Agent Key 不会同时启用 RSS 模型服务。启用外部 AI 时，相应条目内容、关键词或对话会发送给所选服务商，按自己的数据要求决定是否启用。

## COS 与完整稿件同步

RSS 素材推送只创建 Notion Inbox 页面。将 Notion 稿件正文、封面和图片同步为可交付内容时，当前实现需要 COS，即使首次 RSS 流程已成功，也需单独完成配置。

1. 准备专用 COS Bucket，使用最小权限子账号凭据；对象操作需要目标 Bucket 的 `cos:HeadBucket`、`cos:HeadObject`、`cos:PutObject` 权限。
2. Bucket 采用公有读、私有写。公开内容会通过对象 URL 访问，不要放私人稿件资产；按需配置自定义域名、流量告警和防盗链。
3. 在 `infra/self-host/.env` 填写 `COS_BUCKET`、`COS_REGION`、`COS_SECRET_ID`、`COS_SECRET_KEY`、`COS_PUBLIC_BASE_URL`，可保留 `COS_ASSET_PREFIX=assets/sha256`。公开地址使用 HTTPS；API 写入地址由 region 确定。
4. 重建 Reven 容器使环境生效，在专用稿件上验证正文和图片同步。对象使用内容寻址；历史对象不会随本地数据库回滚而删除。

完整稿件库除“标题”和 Status 类型“状态”外，按需添加 **目标渠道**（Multi-select：`个人博客`、`微信公众号`）与 **计划发布日**（Date）。正文由 Notion 页面提供，封面使用初始化创建的 Files 字段。

只有准备好对应渠道后才把测试稿设置为“待发布”。时间以 `Asia/Shanghai` 为准；仅指定日期时按当天 08:01 调度。缺少封面或有效集成会阻止交付。

## 微信公众号草稿

1. 使用自己具有相应接口权限的公众号，在 **集成设置 → 微信** 保存 AppID、AppSecret 和作者，执行连接测试。
2. 登录后访问本实例的 `/api/system/egress-ip`，将返回的固定出口 IP 加入公众号平台白名单；出口变化时先更新白名单。
3. 完成 COS、Notion 正文与封面配置，只给专用测试稿选择“微信公众号”。确认本机 renderer 沙箱可运行，再开启交付。
4. 在公众号草稿箱核对标题、正文图片、封面、作者和草稿 ID；重复尝试前先检查已有任务结果，避免手工另建同一稿件。

Reven 只创建草稿，不调用公开发布或群发流程。最终公开发布由你在公众号平台操作。

## 博客接入边界

**当前 Alpha 不能通过表单配置任意博客站点。** GitHub 客户端的上线校验仍限定维护者站点 origin，表单也没有可自定义的站点地址。仅填写自己的仓库与 Token，不能视为已完成博客接入；先保持测试稿不选择“个人博客”。解除固定站点约束需要独立改造与验收。

博客流程已有的技术前提如下，供评估后续接入，不表示外部站点已受支持：

- Jekyll 博客仓库、自有 Token，以及读写内容、创建/合并 PR、读取检查与分支保护信息的权限。
- 通过独立 PR 将 [博客验证 workflow](../infra/blog/verify.yml) 安装为博客仓库的 `.github/workflows/reven-jekyll.yml`，将 `Jekyll build` 设为默认分支 required check。
- Linux 用户命名空间与 bubblewrap 沙箱可用；构建使用镜像内锁定的受信 Ruby 依赖，不在运行容器里安装博客仓库任意依赖。
- 验收应覆盖创建单个 PR、required check 通过、合并、指定站点上线与重复执行幂等。

维护者已有生产博客仍按 [运行手册](runbook.md) 操作。

## 飞书与费用

“飞书”卡片配置群机器人的 Webhook，用于通知；连接测试会发送真实测试消息。先使用自己的测试群。“飞书应用”是另一项集成，需要自建应用凭据、事件长连接和允许操作的成员 Open ID 白名单；未验证权限前保持停用。

域名、服务器、存储与流量，以及 Notion、翻译、模型、GitHub、微信和飞书的账号或接口服务，均可能产生费用或额度限制。自行在服务商控制台核对，并按需设置预算与告警；Reven 不管理这些账单。
