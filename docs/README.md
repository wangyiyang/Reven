# 产品与架构文档中心

> 更新日期：2026-07-19
> 当前状态：产品主线与五阶段 PRD 已收敛，待业务评审

## 1. 统一结论

本项目建设的不是 Excel 报表网站，也不是一次性重写完整 ERP，而是一个面向多门店家电经销商的 AI 原生经营平台：先把持续变化的 Excel 转成可信事实，再建立经营工作台和智能协作闭环，最后按业务域渐进替代用友，并为 CRM、售后、WMS 和 SRM 等模块保留生长空间。

出现范围或优先级冲突时，以[产品主故事线](./product-storyline.md)和[五阶段 PRD](./prd.md)为准。

## 3. 当前五阶段

| 阶段 | 核心结果 | 关键退出条件 |
|---|---|---|
| Phase 0 安全与事实基线 | 风险受控，有业务确认的黄金样本 | 凭据完成轮换，黄金案例和责任人明确 |
| Phase 1 可信数据层 | 不固定 Excel 稳定进入标准事实 | 幂等、金额守恒、版本链和回归全部通过 |
| Phase 2 经营工作台 | 核心日报与异常不再依赖临时脚本 | 连续两周脱离临时脚本，数字均可下钻 |
| Phase 3 智能协作闭环 | Agent 可查、可解释、可生成受控草稿 | 首条滞销任务闭环全程留痕 |
| Phase 4 用友渐进接管 | 完成首个销售域主权切换 | 销售域单一主写、对账和回退演练通过 |

Phase 4 之后的库存、采购、财务接管，以及 CRM、售后、WMS、SRM 等模块，基于届时的真实流程和数据另立 PRD。

## 5. 已冻结的关键决策

1. 首发按单租户实现，业务模型预留 `tenant_id`，复杂 RLS 延后。
2. 首批覆盖 5 种销货和 3 种库存结构，不建设无限通用解析引擎。
3. 同一来源单据保留版本链，不能用简单 upsert 覆盖历史。
4. 京东 B2B 数据只作外部价格观察，不作商品主数据。
5. MVP 只做提成试算与未匹配治理，不做正式结算。
6. MVP 使用模型 SDK、工具目录和数据库状态机，不依赖 LangChain/LangGraph。
7. Agent 负责理解、解释与草稿；金额、库存和状态由确定性服务负责。
8. 用友按领域切换，同一领域不得长期双写。

## 6. 文档治理

- 主故事线记录稳定产品判断；范围变化先修改主故事线。
- PRD 记录阶段需求和验收；未满足退出条件不得自动扩大范围。
- 详细设计可以演进，但不得反向扩大 PRD 承诺。
- 证据文档保留事实、推断和分歧，不因结论收敛而删除历史判断。
- 新模块启动前必须具备真实流程、真实样本、明确事实所有权和独立 PRD。
