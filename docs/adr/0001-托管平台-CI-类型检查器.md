# ADR 0001: 托管平台 / CI 平台 / 类型检查器选型

- **日期**: 2026-07-20
- **状态**: 已关闭

## 背景

在 Phase 0 环境基线搭建中，需要确定以下三项基础设施决策（来自仓库设计文档 §10 待决策项）：

| # | 事项 | 默认倾向 | 关闭时点 |
|---|------|---------|---------|
| 1 | 托管平台 | GitHub 私有仓 | Phase 0 环境基线 |
| 2 | CI 平台 | GitHub Actions | Phase 0 环境基线 |
| 3 | 类型检查器 mypy vs pyright | mypy | 首个 PR 前 |

## 决策

### 1. 托管平台：GitHub 私有仓库

- 仓库已创建为 `wangyiyang/Reven`，私有可见性。
- 原因：一人团队无需自建托管，GitHub 生态（Actions、PR 保护）天然集成。

### 2. CI 平台：GitHub Actions

- 五步流水线（ruff check → ruff format → mypy → import-linter → pytest）已本地验证通过，配置为 `.github/workflows/ci.yml`。
- 原因：与 GitHub 托管同生态，零额外成本；五步即可覆盖 Phase 1 全部质量门禁。

### 3. 类型检查器：mypy

- 选 mypy 而非 pyright，理由：
  - SQLAlchemy 2.0 Mapped 注解生态中 mypy 插件（sqlalchemy2-stubs）更成熟。
  - uv workspace 下 mypy 多包支持已验证通过。
  - strict 模式已启用，当前 17 个源文件零错误。

## 后果

- 三项决策均在 Phase 0 收尾时关闭，不再留为待决策项。
- 仓库设计文档 §10 表对应行标记为「已关闭」。
- 后续若引入 pyright（如与 IDE 补全配合），可与 mypy 并存但以 mypy CI 结果为门禁标准。
